# PersonaPlex Architecture Overview

## 1. What is PersonaPlex?

PersonaPlex is a **full-duplex conversational speech model** released by NVIDIA (January 2026).
It enables real-time, natural voice conversations where the AI can simultaneously listen and
speak — supporting interruptions, backchannels ("hmm", "yeah"), overlapping speech, and rapid
turn-taking.

**Key innovation**: PersonaPlex decouples **voice identity** from **behavioral role** through
a dual-prompt conditioning system, allowing any voice to play any role.

- **Paper**: [PersonaPlex: Voice and Role Control for Full Duplex Conversational Speech Models](https://arxiv.org/abs/2602.06053)
- **Code**: [github.com/NVIDIA/personaplex](https://github.com/NVIDIA/personaplex)
- **Weights**: [nvidia/personaplex-7b-v1](https://huggingface.co/nvidia/personaplex-7b-v1)
- **License**: MIT (code), NVIDIA Open Model License (weights)

## 2. Architecture Stack

PersonaPlex is built on top of the **Moshi** framework from Kyutai Labs.

```
┌─────────────────────────────────────────────────────────┐
│                    PersonaPlex (7B)                      │
│  Fine-tuned Moshi with dual-prompt conditioning          │
│  (voice prompt + text prompt)                            │
├─────────────────────────────────────────────────────────┤
│                    Moshi Framework                       │
│  Full-duplex speech-to-speech foundation model           │
│  Temporal Transformer (32 layers) + Depth Transformer    │
├─────────────────────────────────────────────────────────┤
│                    Mimi Neural Codec                     │
│  Audio <-> Discrete Tokens (12.5 Hz, 8 codebooks)       │
│  ConvNet Encoder + Transformer + ConvNet Decoder         │
├─────────────────────────────────────────────────────────┤
│                  Helium Language Model                   │
│  Provides semantic understanding (text token prediction) │
└─────────────────────────────────────────────────────────┘
```

### 2.1 Mimi Neural Audio Codec

Mimi converts raw audio into discrete tokens and back. This is the foundational component
that makes speech-to-speech modeling possible.

**Encoding pipeline:**
```
24kHz PCM Audio
    ↓
SEANetEncoder (ConvNet with residual blocks)
    ↓ Downsampling ratios: [8, 5, 4, 2] → total stride = 320
    ↓ Output: 512-dimensional continuous latents at 12.5 Hz
    ↓
Residual Vector Quantization (RVQ)
    ↓ 8 codebooks, each with 2048 entries (bins)
    ↓
8 discrete token streams at 12.5 Hz
```

**Key specifications:**
| Parameter | Value |
|---|---|
| Input sample rate | 24 kHz |
| Frame rate | 12.5 Hz (80ms per frame, 1920 samples/frame) |
| Number of codebooks | 8 (configurable up to 32) |
| Codebook size | 2048 entries each |
| Bitrate | ~1.1 kbps |
| Latency | 80ms (one frame) |

**RVQ mechanism:**
Each codebook captures progressively finer details:
- Codebook 1: coarse acoustic structure (+ semantic info via WavLM distillation)
- Codebook 2-8: residual details (pitch, timbre, fine acoustic texture)

```
x_0 = encoder_output
for i in 1..8:
    q_i = quantize(x_{i-1})    # find nearest codebook entry
    x_i = x_{i-1} - q_i         # compute residual
```

The first codebook is special: it is trained with a **distillation loss** from WavLM
(a self-supervised speech model) so that the first-level tokens capture **semantic** information,
similar to SpeechTokenizer's approach.

### 2.2 Moshi Temporal + Depth Transformers

**Dual-stream processing:**
Moshi processes two simultaneous audio streams:
- **User stream** (input): encoded from microphone by Mimi → `codes[:, 1:9]`
- **Moshi stream** (output): generated by the model, decoded by Mimi

**Token layout per timestep (K=9 streams):**
```
Index 0:    Text token (Inner Monologue)
Index 1-8:  Audio codebook tokens (8 codebooks from Mimi)
```

**Temporal Transformer (main model):**
- 32 layers, 4096 dimensions, 32 attention heads
- Processes temporal dependencies across ALL 9 streams jointly
- Uses causal attention mask (streaming-compatible)
- Rotary positional embeddings (RoPE)
- RMSNorm normalization

**Depth Transformer (inter-codebook):**
- 6 layers, 1024 dimensions
- Models dependencies ACROSS codebooks for a single timestep
- No temporal context (processes one timestep at a time)
- Sinusoidal positional embeddings

### 2.3 Inner Monologue (Text Token Prediction)

The "Inner Monologue" is Moshi's approach to jointly modeling text and audio:
- At each timestep, the model predicts a **text token** (index 0) BEFORE the audio tokens
- This acts as a "semantic plan" guiding audio generation
- Text prediction uses `text_linear: Linear(4096, 32000)` head
- Audio prediction uses separate heads per codebook with 2048 outputs each

**Training tensor format:**
```
codes: [B, K=9, T]
  B = batch size
  K = 9 (1 text stream + 8 audio codebooks)
  T = sequence length (number of 80ms frames)
```

### 2.4 PersonaPlex Dual-Prompt Conditioning

PersonaPlex adds two conditioning inputs before conversation begins:

**1. Voice Prompt (audio embedding):**
- A `.pt` PyTorch tensor file containing voice characteristics
- Extracted from reference audio using Mimi encoder
- Controls: vocal timbre, pitch range, speaking rate, prosody
- 16 pre-packaged voices available (8 female, 8 male)

**2. Text Prompt (natural language, max 200 tokens):**
- Describes the persona: role, background, scenario context
- Examples: "You are a friendly customer service agent for a tech company"
- Controls: linguistic behavior, topic knowledge, response style

```
[Voice Prompt Embedding] + [Text Prompt Tokens] + [Conversation Audio Tokens...]
```

## 3. Inference Pipeline

```
User speaks into microphone
         ↓
    24kHz audio stream
         ↓
    Mimi Encoder → 8 audio token streams at 12.5 Hz
         ↓
    Combined with voice prompt + text prompt
         ↓
    Temporal Transformer (32 layers)
    ├── Processes user audio tokens
    ├── Generates model's text tokens (Inner Monologue)
    └── Generates model's audio tokens
         ↓
    Depth Transformer (6 layers)
    └── Refines audio token predictions across codebooks
         ↓
    Mimi Decoder → 24kHz output audio
         ↓
    Agent speaks (streamed in real-time)
```

**Latency benchmarks:**
- Interruption latency: 240ms
- Turn-taking latency: 170ms
- Smooth turn-taking success rate: 90.8%
- User interruption success rate: 95.0%

## 4. Key Differences from Traditional Systems

| Feature | Cascaded (ASR→LLM→TTS) | PersonaPlex |
|---|---|---|
| Architecture | Pipeline of 3 separate models | Single end-to-end model |
| Duplex capability | Half-duplex (wait for silence) | Full-duplex (simultaneous) |
| Latency | High (sum of all stages) | Low (~170ms turn-taking) |
| Backchanneling | Not possible | Natural ("hmm", "yeah") |
| Interruption handling | Crude (VAD-based) | Native support |
| Voice control | TTS voice only | Decoupled voice + role |
| Emotional expression | Limited | Learned from real data |

## 5. Relevance to Vietnamese Adaptation

**Challenges for Vietnamese fine-tuning:**
1. **Mimi codec**: Trained on English audio. Vietnamese tones (6 tones) need representation
2. **Text tokenizer**: Uses Helium's tokenizer (English-focused, 32K vocab)
3. **Inner Monologue**: Text tokens must support Vietnamese characters
4. **Training data**: Need Vietnamese conversational audio with dual-prompt annotations
5. **Chatterbox TTS**: Used for synthetic data — does NOT support Vietnamese currently

**What needs to change:**
- Retrain or fine-tune Mimi codec on Vietnamese speech data
- Extend or replace text tokenizer to handle Vietnamese
- Create Vietnamese conversational training data (real + synthetic)
- Find/build a Vietnamese TTS for synthetic data generation
- Annotate Vietnamese conversations with persona prompts
